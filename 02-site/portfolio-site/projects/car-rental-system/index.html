Case study

Car Rental Management System

Seven modules over one relational core — cars, customers, employees, contracts, payments and licences — with the invariants pushed down into the database rather than trusted to the UI.

StackASP.NET Core MVC · C# · EF Core · SQL Server · ASP.NET Core Identity · Triggers & stored functions
RoleSole engineer
When2026
SourceGitHub repository

The problem

A rental company's data is all constraints: a car cannot be on two contracts at once, a contract cannot exist without a valid licence, a payment cannot outlive its contract. Enforce those only in C# and they hold until the day someone writes to the database another way.

What I did & decided

  • Modelled the domain across seven modules — cars catalogue, customers, employees, rental contracts, payments, licences and accounts — each with its own controller and a clean MVC separation.
  • Used EF Core with code-first migrations for the schema, but kept constraints, stored functions and triggers in SQL so the invariants live with the data, not only with the application.
  • Added ASP.NET Core Identity for authentication and role-based authorisation over provisioning, pricing and rental history.
  • Committed the SQL scripts and seed data to db/ so the schema is reviewable on its own, without reading the C#.

What came of it

  • The rules survive a direct write. Anything that bypasses the app still meets the same constraints.
  • A reviewer can read the schema without reading the application — which is how a reviewer actually reads.
  • Views stay free of query logic; data access lives where it can be changed once.
