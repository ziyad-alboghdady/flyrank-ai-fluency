Case study

Task Management API

A containerised REST API where ownership is impossible to forget, token revocation is immediate, and the API never stores a password.

Stack.NET 9 Web API · C# · EF Core · PostgreSQL 16 · Docker Compose · Supabase Auth · JWT middleware
RoleSole engineer
When2026
SourceGitHub repository

The problem

A task API is only interesting once more than one person uses it. Then two things get hard: proving who the caller is, and guaranteeing that a caller can never touch another user's rows. Both are easy to get almost right — and “almost right” on an authorisation boundary is indistinguishable from broken.

What I did & decided

  • Split the service into Controllers → Services → Repositories, with ITasksRepository implemented by PostgresTasksRepository over EF Core, so storage stays behind one seam.
  • Made Supabase the identity provider and this API a pure resource server: it never stores a password and never signs a token, it only verifies them. One less thing to get catastrophically wrong.
  • Put authentication in SupabaseAuthMiddleware rather than in controllers, so controllers contain no auth code at all. ErrorHandlerMiddleware wraps it from the outside, so an exception thrown by the auth guard is still handled.
  • Chose a network round-trip over a local JWKS signature check. Local verification is microseconds; the round-trip costs latency and fails when Supabase is down. I took the slower option because it rejects a revoked token immediately, where a local check honours it until it expires. When Supabase is unreachable the API returns 503, not 401 — an outage is not the caller's fault, and re-authenticating cannot fix it.
  • Made ownership a required parameter on every repository query rather than a check inside each method, so it cannot be omitted by accident. The owner is always taken from the verified token, never the request body.
  • Requesting someone else's task returns 404, not 403 — a 403 would confirm that the id exists.
  • All configuration comes from environment variables; appsettings.json holds no secrets and no connection string. Missing config throws at startup with a readable message instead of a null reference on the first request.

What came of it

  • Cross-user access is structurally impossible, not policed: the query will not compile without an owner.
  • A revoked session stops working on the next request rather than at token expiry.
  • docker compose up brings the API and PostgreSQL 16 up together with a named volume, so data survives a reboot and a reviewer can run the whole thing without installing a database.
  • The trade-off table is in the README, because the interesting part of this project is the decision, not the CRUD.
